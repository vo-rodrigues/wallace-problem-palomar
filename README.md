# The Wallace problem in ZFC — Palomar Comparator wrapper

This repository is the small, auditable Palomar wrapper for the Lean 4
formalization accompanying:

> Juliane Trianon Fraga and Vinicius de Oliveira Rodrigues,
> *The Wallace problem and countably compact torsion-free Abelian groups in
> ZFC*, [arXiv:2608.17317v1](https://arxiv.org/abs/2608.17317v1), 2026.

The substantive proof lives in the public
[`wallace-problem-zfc-paper`](https://github.com/vo-rodrigues/wallace-problem-zfc-paper)
repository. This wrapper fixes it at commit
[`23756864de1f14e272dafb070b97fcdc7cbc75c5`](https://github.com/vo-rodrigues/wallace-problem-zfc-paper/commit/23756864de1f14e272dafb070b97fcdc7cbc75c5)
and exposes two Mathlib-only statements to
[`leanprover/comparator`](https://github.com/leanprover/comparator).

## Results recorded

Comparator checks these two declarations:

- `Wallace.Palomar.torsionFreeAbelianGroup_mainTheorem`: every torsion-free
  Abelian group of cardinality continuum admits a Hausdorff countably compact
  group topology in which every convergent sequence is eventually constant;
- `Wallace.Palomar.commutativeTychonoffWallaceCounterexampleExists`: there is a
  commutative Tychonoff countably compact topological additive monoid with
  two-sided cancellation and a noninvertible element, hence one that is not a
  group. This is the formalized negative answer to Wallace's question.

The work is directed at researchers in topological groups, topological
semigroups, and general topology: it supplies an unconditional group-topology
construction and resolves the longstanding Wallace problem in the negative.

## What to audit

[`Challenge.lean`](Challenge.lean) is the statement of record. It imports only
Mathlib, explains the intended mathematics, and contains the two deliberate
`sorry` holes that stand for the advertised proofs.

[`Solution.lean`](Solution.lean) imports the pinned proof library and bridges
its public theorems to exactly the same names and types. The declarations in
[`comparator.json`](comparator.json) are checked with only these permitted
axioms:

```text
propext
Classical.choice
Quot.sound
```

The substantive development is sorry-free. Its own `StatementAudit.lean`
independently restates the public propositions, and `Audit.lean` traverses
their dependencies and rejects every axiom outside the three above.

## Reproduce the checks

Install [elan](https://github.com/leanprover/elan) and Ruby 3.3, then use the
committed manifest without updating dependencies:

```text
lake env lean --version
lake exe cache get
lake build
ruby scripts/validate-formalization.rb
```

The first command must report Lean `4.30.0`. The Challenge build emits exactly
two expected warnings for its deliberate proof holes; the Solution and the
underlying proof do not rely on them.

On Linux, with Git, Go 1.24, Rust/Cargo, Python 3, and elan/Lake installed, the
full pinned Comparator/NanoDa check is:

```text
./scripts/verify-comparator.sh
```

It downloads pinned revisions of Comparator, `lean4export`, NanoDa, and
Landrun, then performs the same statement/proof comparison exercised by CI.

## Provenance, scope, and review

The Palomar configuration selects the universal theorem and the resulting
Wallace counterexample. Specializations and internal consequences in the
underlying library are not separately selected.

“In ZFC” is represented by a classical Lean proof with no additional
set-theoretic or project-specific axiom. Lean's type theory, kernel, and the
pinned Mathlib definitions remain the trusted boundary; the project does not
claim to formalize ZFC.

The formalization was generated by OpenAI Codex, powered by the GPT-5.6 Sol
model, in an iterative process directed by the authors. The authors supplied
the mathematical objectives, context, constraints, ideas, and feedback,
selected the released artifact, and take responsibility for it. The work has
been self-assessed by the authors; no independent human peer review of the Lean
code is claimed. Full structured disclosure is in
[`formalization.yaml`](formalization.yaml).
